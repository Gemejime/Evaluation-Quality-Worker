## Non-Negotiable Invariants

1. **Continuous Doc API Updates**: The [`.ai/doc-api.md`](.ai/doc-api.md) file and the OpenAPI 3.1 schemas MUST be kept updated on **every code change or addition**, regardless of how small the modification is.
2. **Secured Logging**: All logging must be structured JSON. Strictly redact PII/PHI, golden-set raw prompt/context text spans, customer secrets, authorization headers, presigned URLs, and KMS salts before emission.
3. **Decoupled Architecture**: Real-time chunk tokenization (`rag-masking-sanitizer`) is decoupled from batch LLM-as-a-judge pipelines (`rag-eval-worker`) to prevent memory contention and queue cross-talk.
4. **Standardized Lean Evaluation Engine**: Use native prompt-based evaluation adapters directly against Triton/vLLM endpoints for Context Precision, Faithfulness/Groundedness, and Answer Relevance. Heavy third-party frameworks (Ragas/TruLens) are excluded from runtime dependencies.
5. **Zero-Allocation Egress & Direct ClickHouse Micro-Batching**: Persist run metadata and score distributions directly to ClickHouse MergeTree tables (`evaluation_runs`, `eval_metric_points`) without transactional dual-writes to relational databases.
6. **Temporal Heartbeat Reliability**: 100% of batch evaluation tasks heartbeat every 10 seconds per evaluated sample, enabling zero-recompute resumption upon pod preemption.
7. **Outbound Judge Rate Limiting**: Outbound judge calls are governed by a token-bucket rate limiter and concurrency semaphores (capped at 20 concurrent judge requests) with full jitter exponential backoff on HTTP 429.
8. **Memory Bounds**: Flat Resident Set Size (RSS) $\le 2.0$ GiB per eval worker under prolonged execution using `jemalloc` preloading (`LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libjemalloc.so`).
9. **Code Cleanliness**: All code must pass `ruff check`, `ruff format --check`, and strict `mypy` typechecks.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features 
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

---

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Run Ruff linter and formatter: `python -m ruff check --fix .` and `python -m ruff format .`.
2. Run static type analysis: `mypy cmd internal test`.
3. Run test suites: `pytest test/unit test/integration`.
4. Verify [`.ai/doc-api.md`](.ai/doc-api.md) and OpenAPI 3.1 schemas are updated with all API, schema, or storage modifications.
5. Verify Secured Logging rules: Ensure no raw text, secrets, or PII are logged.
6. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
